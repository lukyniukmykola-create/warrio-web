# Warrio Web — пакет для публікації

Ця папка містить production-ready статичний frontend Warrio Web:

- `index.html` — адміністративний інтерфейс Warrio;
- `config.js` — лише браузерна конфігурація Supabase;
- `backend.js` — безпечна перевірка доступності API;
- `auth.js` — Supabase Auth, відновлення й оновлення сесії;
- `data.js` — завантаження приватних даних через RLS та бізнес-RPC;
- `auth-ui.js` / `auth-ui.css` — вхід, реєстрація, magic link і створення організації;
- `verify/` — публічна перевірка гарантії без персональних даних;
- `activate/` — безпечна активація покупцем за одноразовим кодом;
- `.nojekyll` — коректна робота статичних файлів на GitHub Pages.

## Безпека

У GitHub дозволено публікувати `sb_publishable_...` ключ. Він не є секретом і
працює тільки в межах прав RLS/RPC. Ніколи не додавайте сюди:

- `service_role` або `sb_secret_...`;
- пароль бази;
- `WARRIO_IMPORT_KEY`;
- Google OAuth client secret, access token або refresh token;
- журнали з локальними даними.

## Що вже працює

- адаптивний адміністративний прототип;
- справжній health-check Supabase через безпечну публічну RPC;
- справжня публічна перевірка за токеном через Supabase;
- локальні демонстраційні сценарії інтерфейсу без входу;
- production-вхід через email/пароль або magic link;
- завантаження реальних даних відповідно до ролі;
- реєстрація продажу, активація гарантії та підтвердження монтажу через атомарні RPC.
- KPI, графіки, рейтинг дилерів і аудит із реальних записів;
- одноразове публічне посилання після активації;
- запрошення команди через захищену Edge Function `invite-member`.
- автоматичний український PDF із реальним QR, приватне Storage-збереження та Resend email;
- CRM-завдання, пріоритети, терміни, проблемні записи й рольовий журнал подій.

## Що свідомо не ввімкнено

Приватні таблиці продажів, клієнтів і гарантій не читаються без входу. Це
правильна поведінка RLS. Реєстрація та лист-запрошення потребують налаштованої
пошти Supabase Auth. Відправка PDF реалізована через Resend, але перед запуском
адміністратор має додати server-side secrets і підтвердити домен. Гарантійний
строк залишається порожнім, доки бізнес не затвердить 24 або 36 місяців.

## Публікація через GitHub Pages

Завантажте вміст цієї папки в корінь репозиторію `warrio-web`. Пакет уже має
`.github/workflows/deploy-pages.yml`. У `Settings → Pages` виберіть джерело
`GitHub Actions`; після кожного push у `main` сайт публікуватиметься автоматично.

Якщо Actions не потрібні, видаліть `.github` і виберіть `Deploy from a branch`,
`main`, `/ (root)`.

Публічна перевірка буде доступна за адресою:

`https://<github-user>.github.io/warrio-web/verify/?token={token}`
